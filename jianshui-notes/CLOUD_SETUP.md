# 柬税笔记 · 云开发（后台管理）配置指南

本文档说明如何为「柬税笔记」小程序接入 **微信云开发（CloudBase）**，实现内容的后台管理。

> 方案：微信云开发 + 云后台。个人主体小程序可直接使用，免域名备案、免配置「合法域名」，云后台自动生成内容管理界面。

---

## 一、工作原理

代码已改造为「**云数据库优先、本地静态数据兜底**」：

- 已开通云开发 + 配置好环境 ID + 创建集合 + 设置权限后，小程序读取云端数据，可在云后台实时增删改查。
- 未开通 / 环境未配置 / 读取失败时，自动回退到 `utils/data.js` 的静态数据，**小程序始终可用**。

涉及文件：
| 文件 | 作用 |
|------|------|
| `app.js` | `onLaunch` 中 `wx.cloud.init()`，`globalData.cloudEnv` 存放环境 ID |
| `utils/db.js` | 云数据库读取封装，含静态兜底 |
| `utils/data.js` | 本地静态数据（兜底用，也作为初始内容） |
| `db/*.json` | 4 个集合的种子数据，供云端导入 |
| `pages/*/index.js` | 改为异步从 `db.js` 取数 |

云端集合（名称需与代码一致）：
| 集合名 | 内容 |
|--------|------|
| `tax_law` | 柬埔寨税法（12 条） |
| `travel_spot` | 柬埔寨旅游景点（8 条） |
| `specialty` | 柬埔寨特产（12 条） |
| `qa` | 柬埔寨问答知识库（16 条） |

---

## 二、开通云开发并获取环境 ID

1. 用**注册该小程序的微信账号**打开微信开发者工具，导入本项目。
2. 顶部工具栏点击 **「云开发」** 按钮 → 开通云开发（按提示创建环境，环境名称随意，如 `jianshui`）。
3. 开通后在云开发控制台左上角能看到 **环境 ID**（形如 `jianshui-1a2b3c`）。复制它。
4. 打开 `app.js`，把占位符替换成你的环境 ID：
   ```javascript
   globalData: {
     cloudEnv: 'jianshui-1a2b3c'   // ← 替换成你的真实环境 ID
   }
   ```
   > 注意：此处仍为 `'your-cloud-env-id'` 时，代码不会初始化云能力，小程序走静态数据。

---

## 三、创建集合并导入种子数据

1. 云开发控制台 → **「数据库」** → 新建集合，依次创建：
   `tax_law`、`travel_spot`、`specialty`、`qa`
2. 进入每个集合 → **「导入」** → 选择项目里对应的种子文件：
   | 集合 | 导入文件 |
   |------|---------|
   | `tax_law` | `db/tax_law.json` |
   | `travel_spot` | `db/travel_spot.json` |
   | `specialty` | `db/specialty.json` |
   | `qa` | `db/qa.json` |
   > 导入文件为 JSON 数组格式（每个文档一行对象），直接导入即可。
3. **权限设置（关键）**：每个集合 → 「权限设置」→ 选择
   **「所有用户可读，仅创建者可读写」**（或自定义：读 = true）。
   > 若不放开读权限，小程序端读取会失败，自动回退静态数据，后台管理不生效。

完成以上步骤后，重新编译小程序，首页/税法/旅游/特产/问答即改为读取云端数据。

---

## 四、使用云后台管理内容

1. 云开发控制台 → **「云后台」**（或「扩展能力 → 云后台」）→ 开通。
2. 云后台会自动为上述 4 个集合生成**管理界面**，你可以：
   - 新增 / 编辑 / 删除税法、景点、特产、问答条目
   - 上传/修改字段（如特产图片名 `img`、价格 `price`、标签 `tags`）
3. 保存后，小程序端刷新即可看到最新内容，**无需重新发版**。

> 字段说明（与代码取数对应）：
> - `tax_law`：`id`(数字)、`category`、`title`、`summary`、`content`、`tags`(数组)
> - `travel_spot`：`id`、`category`、`name`、`image`(emoji)、`location`、`rating`、`summary`、`content`、`tips`(数组)、`season`
> - `specialty`：`id`、`category`、`name`、`image`(emoji)、`img`(图片文件名，对应 assets/images/)、`price`、`rating`、`summary`、`content`、`tags`(数组)
> - `qa`：`keywords`(数组)、`reply`
>
> 分类（`taxLawCategories` 等）与首页 `banners`/`quickEntries` 仍写在 `utils/data.js` 中，一般不常变动，如需改动直接改代码。

---

## 五、重新生成种子数据（可选）

若修改了 `utils/data.js` 的静态内容，可重新导出种子 JSON：
```bash
node build-seed.mjs
```
会在 `db/` 下重新生成 4 个集合文件。

## 六、常见问题

| 现象 | 原因 / 解决 |
|------|------------|
| 内容没变化，仍是旧数据 | 未开通云开发，或 `app.js` 的 `cloudEnv` 还是占位符 → 按第二节配置 |
| 报错 `wx.cloud is not defined` | 未在开发者工具开通云开发，或基础库版本过低（需 ≥ 2.2.3） |
| 页面空白/回退静态数据 | 集合权限未放开「所有用户可读」→ 按第三节第 3 步设置 |
| 导入失败 | 确认导入的是 `db/*.json`（JSON 数组），不要导入 `utils/data.js` |
| 真机调试报 `41002 appid missing` | 与云开发无关，是 `project.config.json` 的 AppID 仍为占位符 `wx0000000000000000`，需换成真实 AppID |
