# KHMER AI 2.0 — 2026 微信小程序开发大赛版
## 整改方案（编号 KHMER-1.1.1）

> 基于现有 `cambodia-biz-travel` 原生小程序整改。结论：**可行**，现有三语 i18n + 税务/物业核心逻辑可复用，省约 50%~60% 前端工作量；后端与 AI 从零搭建。

---

### 一、产品定位（一句话）
面向**在柬埔寨的中资企业 / 出海商务人群**的一站式助手：用 **AI 助手** 理解自然语言需求，自动生成**需求单**，并在 **住宿 / 企业需求 / 供应链匹配 / 物业管理** 四大业务中完成**小程序内需求单闭环**。

### 二、六大模块映射
| 模块 | 来源 | 改造方式 |
|---|---|---|
| AI助手 | 空白 | 后端 `/api/ai/chat` 接入微信AI生态（provider 可插拔），多轮对话 + 意图识别 → 一键生成需求单 |
| 住宿 | 仅展示 | 升级为「住宿需求单」，匹配柬埔寨酒店目录 |
| 企业需求 | 空白 | 企业发布采购/服务需求 → 需求单 |
| 供应链匹配 | 空白 | 供应商目录 + 规则/AI 匹配引擎 → 推荐并接单 |
| 物业管理 | 已有台账 | 复用抄表/账单，转为「物业工单」类需求单接入闭环 |
| 需求单闭环 | 空白 | **中枢**：待处理→匹配中→已接单→处理中→已完成→已评价 |

### 三、技术架构
```
小程序前端 (miniprogram/)
   │  wx.request → HTTPS
   ▼
自托管后端 (server/ Node+Express+SQLite，部署于海外 VPS)
   ├─ /api/auth/login      wx.login code2Session 换 openid + token
   ├─ /api/ai/chat         AI 助手（微信AI生态 / 大模型，可降级）
   ├─ /api/requirement    需求单 CRUD + 状态推进
   └─ /api/match          按类型做住宿/供应链/物业匹配推荐
```
- 后端用 `better-sqlite3`（文件库，零外部依赖，便于海外轻量部署）。
- 鉴权：`/api/auth/login` 用 `APPID+APPSECRET` 调微信 `code2Session` 换 openid，签发 HMAC token。
- AI provider 抽象：默认 OpenAI 兼容网关，环境变量切换为**微信AI/元宝**网关即可"接入微信AI生态"；无密钥时规则降级，保证离线可演示。
- ⚠️ **微信AI生态接入是参赛硬性前提（主题"与AI共生"）**：赛事规程明确要求"接入微信AI生态"。因此 AI 模块默认优先对接微信AI/元宝网关，降级模板仅作离线兜底，正式参赛版必须跑通真实 AI 调用。

### 五、海外小程序合规清单（"符合海外小程序开发规则"）
- **类目**：住宿→【旅游-酒店服务】；物业→【房地产/生活服务】；企业/供应链→【商业服务】；**AI 助手→【深度合成-AI问答】**。需营业执照原件+翻译。
- **AI 策略**：因小程序提供 AI 问答/文本生成能力，审核要求必须补充【深度合成-AI问答】类目；同时**所有 AI 生成页面须显著标识"AI生成"或同等含义字样**。
- **服务器**：自托管需部署在海外（保留物理位置证明）。
- **域名**：小程序后台「服务器域名」添加后端 HTTPS 域名（request 合法域名）。
- **隐私**：提供英文版隐私政策，符合当地数据法规。
- **内容**：不涉政治/宗教/敏感议题，三语（已有）本地化。
